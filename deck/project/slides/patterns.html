Reliability patterns

Seven patterns, stacked like middleware

PatternProtects againstWatch out for
Retry + backoff + jitterTransient faultsRetrying writes, retry storms
Idempotency keysDuplicate side effectsKeys must be stable on replay
CheckpointingCrashes mid-runSave after every step
Circuit breakerHammering a dead dependencyTune threshold and cooldown
FallbackA dependency being downLabel degraded data as such
Graceful degradationLosing a capabilityQueue it; never fake success
BudgetsLoops, runaway spendSteps, dollars, repeated calls

with_fallback(with_retry(with_breakers(idempotent(tool))))

Every wrapper has the same signature, so they compose, as in the footer. Order matters. The breaker sits inside retry so it can count every failed attempt and fail fast once open; idempotency sits innermost so every attempt carries the key. In LangGraph the same ideas appear as RetryPolicy on nodes, checkpointers for durable execution, and interrupt for human steps.
