Chaos experiment

Turn up the fault rate and watch which configuration holds

The setup

  • Fault rates: 0%, 20%, 40% of tool calls
  • Configurations: unprotected, retry only, full stack
  • Seeded faults, so every run is reproducible
  • Measure success rate and latency

What to look for

  • How fast each line falls as faults rise
  • Where retry-only still fails: writes it won't retry
  • Latency paid for resilience
  • Degraded outcomes that are honest, not faked
The numbers come from the live run. Do not predict them on the slide. Point out that success here means the oracle is satisfied, and a refund queued for a human is not the same as a refund issued. Ask whether the task definition should count honest degradation as success. That is a product decision, not an engineering one.
