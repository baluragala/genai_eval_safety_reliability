The world your agent depends on fails too

FaultLooks likeRetry it?
TimeoutUpstream took 5 s, gave upYes, with backoff
Rate limit429 with retry-afterYes, after retry-after
Server error503 service unavailableYes, a few times
Bad request400: your arguments are wrongNo, it will fail again
CrashThe worker dies mid-runResume from checkpoint

FaultInjector reproduces all of these with a seed. Backoff runs on a virtual clock, so class never waits.

Start Notebook 05 by running the golden set with 30% of tool calls failing and no protection, and let the room see the success rate drop. Then classify faults: retryable versus permanent. Retrying a 400 just burns time and money. Crashes are different in kind: the process is gone, so what matters is what you saved before it died.
