Retries alone multiply the load on a dead service. The breaker turns a slow failure into a fast one, which the fallback can then handle.

In the notebook, one shared breaker protects the orders database while five customers hit an outage. Compare how many calls reach the dead database with retry only versus retry plus breaker; the notebook counts them live. Then the fallback serves order status from a read replica, labelled as possibly stale, and refunds are queued for a human instead of failing.
